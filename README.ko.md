# writing-styles-from-giants

[English](README.md)

앞선 시대의 사상가와 역사적 인물, 영향력 있는 책, 널리 알려진 기업과 기관의 글쓰기·설명 방식을 AI 에이전트가 활용할 수 있는 스킬로 만드는 프로젝트입니다.

이름에는 **거인들의 어깨에서 세상을 바라보자**는 뜻을 담았습니다. 앞선 이들이 쌓아 온 지식과 실천에서 배웁니다. 여기서 글쓰기 방식은 문장 표현, 논증 구조, 설명 방식, 문서 작성 관행을 포함합니다. 목표는 **문서화된 출처 → 출처를 밝힌 방법론 → 에이전트 스킬 → 작업에 맞는 적용**으로 이어지는 흐름입니다.

**현재는 기반을 마련하는 단계입니다.** 프로젝트 문서, 작성 예제, 로컬 검사, CI·릴리스 워크플로 정의가 있습니다. 설치 가능한 방법론 스킬, 추천 워크플로, 프로젝트 전용 설치 도구는 아직 없습니다. GitHub에서 기반 검사 CI는 통과했으며, 릴리스 워크플로와 도구별 호환성은 아직 검증하지 않았습니다.

## 이 프로젝트를 시작한 이유

평소 AI에게 “간결하게 써 줘”, “핵심 내용을 정리해 줘”처럼 글쓰기 요구사항을 두루뭉술하게 전달하곤 했습니다. 그 결과 제가 생각한 것과 다른 정리본을 받거나, 읽고 싶지 않은 “AI slop”이 만들어졌습니다.

이 프로젝트는 그런 고충에서 시작했습니다. 과거 현인들의 글쓰기·설명 방식과 유명 기관의 글쓰기 가이드를 차용해, 출처와 적용 기준이 분명한 스킬로 정리하려 합니다. 어떤 순서로 생각을 구성하고, 독자에게 어떻게 설명하며, 무엇을 강조할지 AI에 구체적으로 요구하는 것이 목표입니다.

## 방법론

아래 초기 후보는 제안이며, 출처·권리 검토, 규칙 작성, 영어·한국어 검토가 필요합니다. 유명하다는 이유만으로 규칙의 근거가 되지는 않습니다.

| 후보 | 활용 목적 | 상태 |
| --- | --- | --- |
| Orwell의 원칙을 참고한 평이한 글쓰기 | 명확한 문장 표현 | 제안 단계, 스킬 없음 |
| Federal Plain Language Guidelines | 독자 중심의 설명 | 제안 단계, 스킬 없음 |
| Minto의 원칙을 참고한 구조화 | 제안과 논증의 구성 | 제안 단계, 스킬 없음 |

[출처 참고 자료](THIRD_PARTY_NOTICES.md)와 [프로젝트 정의](docs/PROJECT.md)를 확인하세요. 방법론이 준비되면 목록에서 실제 `SKILL.md`로 연결하고 언어별 지원과 검토 상태를 표시합니다. `templates/`와 `evals/`는 작성용 예제이며, 배포된 방법론이나 모델 평가 결과가 아닙니다.

## 설치

실제 방법론 목록이 아직 없어 설치 명령을 제공하지 않습니다. 기존 설치 도구로 저장소의 스킬을 배포하는 데 이 프로젝트 자체의 npm 패키지가 필요한 것은 아닙니다.

첫 배포에서는 자체 CLI를 만들기 전에 기존 스킬 설치 도구를 검토하는 방안을 제안합니다. 스킬 디렉터리 전체 설치, 프로젝트 범위, 충돌 처리, 갱신·제거를 검증한 뒤 설치 안내를 공개합니다. 자세한 기준은 [설치 계약](docs/ARCHITECTURE.md)을 확인하세요.

## 계획된 동작

- 방법론을 직접 선택하거나 추천을 요청하고, 적용을 끌 수 있습니다. 자동 적용은 사용자가 선택한 범위에서만 수행합니다.
- `light`, `standard`, `strict` 단계를 제공합니다. 모든 단계에서 사실, 수치, 단위, 부정, 조건, 예외, 불확실성, 인용문, 출처 표시, 코드를 보존합니다.
- 영어·한국어부터 시작합니다. 각 언어에 맞게 규칙과 평가를 조정하며, 영어 단어 수 제한을 한국어 어절 수 제한으로 고정 환산하지 않습니다.
- 공통 스킬 본문은 도구별 기능과 권한에 의존하지 않게 유지합니다. Codex, Claude Code, OpenCode, Antigravity, Pi, Cline은 지원 목표이며, 검증된 연동은 아닙니다.
- 출처를 밝힌 방법론을 적용합니다. 특정인 사칭, AI 작성 여부 판별, 공식 규정 준수 인증은 범위에 포함하지 않습니다.

## 기여

[CONTRIBUTING.md](CONTRIBUTING.md)부터 읽어 주세요. 이슈와 PR은 각각 한 가지 문제에 집중하며, 방법론·언어 변경에는 출처 근거와 예제가 필요합니다. 영문 기여 문서가 기준이며, 영문·한국어 README의 절 순서, 표, 명령어, 의미를 함께 맞춥니다.

첫 정식 `0.0.1` 릴리스 전까지는 단독으로 개발합니다. 완료한 변경은 별도 브랜치에서 신속히 커밋하고 PR을 만들어, CI를 확인한 뒤 병합합니다. 저장소가 private인 동안에는 소유자의 허용에 따라 직접 병합할 수 있으며, 자세한 기준은 [검토 정책](CONTRIBUTING.md)을 따릅니다.

저장소 루트에서 Python 3.12 이상으로 다음 검사를 실행합니다. 추가 패키지는 필요하지 않습니다.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check_repository.py
git diff --check
```

이 검사는 저장소 기반을 확인하며, LLM 글쓰기 품질, 원전 이용 권리, 도구별 활성화는 검증하지 않습니다. 모든 커밋은 향후 오픈 소스 공개를 전제로 준비합니다. 보관할 비공개 파일은 생성·사용하기 전에 `.gitignore`에 등록하며, `private/`와 `.local/`은 로컬 보관용 디렉터리입니다. 작업 중 만든 임시 파일은 제외 규칙을 추가해 남겨 두지 않고 작업이 끝나면 삭제합니다. 제외 규칙만으로 이미 Git에 등록한 파일이 비공개가 되지는 않습니다.
